WEB mini-IDS

웹 요청 로그에서 SQL Injection, XSS와 Path Traversal 흔적을 찾아 이벤트로 정리하는 연습용 도구입니다.

형태
개인 보안 프로젝트
역할
기획 · 설계 · 구현
기술
Python · PySide6 · 정규표현식 · 규칙 기반 탐지
입력
웹 요청 · 로그 데이터
출력
공격 유형 · 위험도 · 탐지 근거

만든 이유

웹 로그를 눈으로 확인하다 보면 긴 요청 사이에 섞인 공격 흔적을 놓치기 쉬웠습니다. 자주 접하는 SQL Injection, XSS, Path Traversal 패턴을 직접 규칙으로 정리하고, 어떤 입력이 어떤 이유로 탐지됐는지 한 화면에서 확인하려고 만들었습니다.

목표는 실제 상용 IDS를 대신하는 것이 아니라 요청을 파싱하고 규칙을 적용해 이벤트로 만드는 기본 흐름을 직접 구현해 보는 것이었습니다.

전체 처리 흐름

구조를 단순화한 예시
request = parse_input(raw_log)
normalized = normalize(request)

matches = detect(normalized, rules)
severity = calculate_severity(matches)

event = build_event(request, matches, severity)
event_view.add(event)

입력 파싱, 정규화, 규칙 검사, 위험도 계산, 화면 표시를 각각 분리했습니다. 규칙을 수정해도 GUI 코드를 같이 바꾸지 않도록 탐지 결과를 공통 이벤트 형식으로 넘깁니다.

요청을 먼저 정규화했습니다

정규화 과정 · 예시
def normalize(value: str) -> str:
    value = url_decode(value)
    value = html_unescape(value)
    value = value.lower()
    return collapse_whitespace(value)

같은 입력도 URL 인코딩, 대소문자와 공백에 따라 모양이 달라질 수 있습니다. 원본 요청은 그대로 보관하고, 탐지용 복사본만 디코딩하고 정리해 규칙에 전달했습니다.

구분화면에는 원본 요청과 정규화된 탐지 근거를 따로 표시해 어떤 변환 뒤에 규칙이 맞았는지 확인할 수 있게 했습니다.

규칙을 나눈 방식

규칙 정의 · 예시
rules = [
    Rule("SQLI", check_sqli, severity="high"),
    Rule("XSS", check_xss, severity="medium"),
    Rule("TRAVERSAL", check_traversal, severity="high"),
]

for rule in rules:
    result = rule.check(normalized_request)
    if result.matched:
        matches.append(result)

공격 유형마다 규칙을 분리하고, 탐지 함수는 일치 여부와 근거를 함께 반환하도록 했습니다. 단순 키워드 하나만 찾기보다 경로, 파라미터, 특수문자 조합과 인코딩 흔적을 같이 확인했습니다.

  1. SQL Injection쿼리 문법, 주석, 논리 연산자와 특수문자의 조합을 확인합니다.
  2. XSS태그, 이벤트 속성과 스크립트 실행에 사용되는 패턴을 확인합니다.
  3. Path Traversal상위 경로 이동과 인코딩된 경로 구분자를 확인합니다.
  4. 위험도일치한 규칙의 종류와 개수를 기준으로 이벤트 우선순위를 정합니다.

탐지 결과 형식

event.json · 예시
{
  "type": "SQLI",
  "severity": "high",
  "source": "query.username",
  "evidence": "논리 연산자와 주석 패턴 일치",
  "request": "원본 요청 데이터"
}

탐지 결과에는 공격 유형과 위험도만 넣지 않고, 요청의 어느 부분에서 어떤 신호가 발견됐는지도 함께 저장했습니다. 이벤트를 클릭하면 원본 요청과 탐지 근거를 같이 확인할 수 있게 했습니다.

PySide6 화면

왼쪽에는 입력한 로그를, 오른쪽에는 탐지된 이벤트를 표시하도록 구성했습니다. 이벤트 목록에서 항목을 선택하면 공격 유형, 위험도와 일치한 규칙을 확인할 수 있습니다.

화면으로 전달되는 데이터
detector.detect(request)
        ↓
DetectionEvent(type, severity, source, evidence)
        ↓
EventTableModel

PySide6 event view

만들면서 확인한 점

규칙 기반 탐지는 결과의 이유를 설명하기 쉽지만 입력 형태가 조금만 달라져도 놓치거나 정상 요청을 공격으로 판단할 수 있습니다. 탐지 규칙을 늘리는 것보다 정탐과 오탐 샘플을 같이 모으고 기준을 조정하는 과정이 중요했습니다.
