01 / OVERVIEW

웹 요청에서 자주 보이는 공격 패턴을 규칙으로 분리했습니다.

웹 요청 로그나 트래픽 데이터를 입력받아 SQL Injection, XSS, Path Traversal 등 주요 패턴을 확인합니다. 탐지 결과는 공격 유형, 위험도, 근거를 포함한 이벤트 형태로 정리해 GUI에서 볼 수 있도록 구성했습니다.

02 / FLOW

입력부터 이벤트 표시까지 한 흐름으로 연결했습니다.

01
Input로그 또는 요청 데이터 정규화
02
Detection정규표현식과 키워드 규칙 적용
03

04
Dashboard탐지 이벤트와 상세 내용 표시
03 / RULES

한 단어보다 요청 안의 여러 특징을 같이 봅니다.

정상 요청이 공격으로 분류되는 경우를 줄이기 위해 경로, 파라미터, 특수문자 조합, 인코딩 흔적 등을 함께 확인하는 방식으로 규칙을 구성했습니다.

  • SQL Injection, XSS, Path Traversal 규칙 분리
  • 입력 파싱과 탐지 규칙을 별도 로직으로 구성
  • 탐지 결과에 유형과 위험도 저장
  • 규칙을 추가할 때 UI 코드를 수정하지 않도록 분리
04 / UI

탐지 이벤트를 확인할 수 있는 화면을 만들었습니다.

PySide6 기반 화면에서 로그와 탐지 결과를 확인할 수 있게 구성했습니다. 탐지 로직과 UI를 분리해 규칙을 수정하거나 추가해도 화면 쪽 코드를 크게 건드리지 않도록 했습니다.

event {
  type: "SQLI | XSS | TRAVERSAL",
  severity: "...",
  source: "request path / parameter",
  evidence: "matched signal"
}
05 / RESULT

기본적인 탐지 흐름을 직접 구현했습니다.

요청 데이터를 읽고, 규칙을 적용하고, 결과를 이벤트로 정리해 화면에 표시하는 흐름을 한 프로젝트 안에서 구현했습니다. 규칙 기반 탐지에서 어떤 조건을 넣느냐에 따라 오탐이 달라진다는 점도 확인할 수 있었습니다.
