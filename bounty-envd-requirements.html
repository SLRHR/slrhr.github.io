envd requirements 경로 이탈과 TOCTOU

처음에는 requirements 경로가 빌드 컨텍스트 밖으로 나가는 문제를 제보했습니다. 1.3.5 패치가 나온 뒤 다시 확인하다가, 검사와 파일 열기 사이의 레이스를 추가로 발견했습니다.

requirements를 읽는 위치

install.python_packages(requirements=...)는 빌드 명령을 만들기 전에 requirements 파일을 호스트에서 읽습니다. 파일 내용은 의존성 목록으로 해석되고, 조건에 따라 pip 설치 단계에 직접 들어갑니다.

여기서 확인한 건 경로의 기준이었습니다. 빌드 컨텍스트 안의 파일을 기대하는 기능인데, 처음 구현에는 호스트에서 읽을 경로가 컨텍스트 안에 머무는지 검사하는 과정이 없었습니다. 제가 처음 제보한 문제는 이 경로를 통해 컨텍스트 밖 파일까지 읽을 수 있다는 점이었습니다.

처음 문제가 된 흐름 · 개념도
requirements 경로 입력
    → 호스트에서 파일 열기
    → 내용을 의존성 항목으로 해석
    → 빌드 단계와 로그에 반영

호스트 쪽 requirements 읽기 동작은 be78326에서 들어왔습니다. 해당 동작이 포함된 최초 릴리스는 0.3.38입니다.

첫 번째 수정, 그리고 다시 확인한 부분

첫 패치 f576c92는 입력 경로를 검사하고, 컴파일 시점에 filepath.EvalSymlinks로 심볼릭 링크를 풀어 빌드 컨텍스트 밖으로 나가는지 확인했습니다. 이 수정은 1.3.5에 포함됐습니다.

패치를 보고 다시 읽으면서 걸린 부분은 검사한 대상과 실제로 연 대상이 같은 파일이라고 보장할 수 없다는 점이었습니다. EvalSymlinks는 확인 당시의 경로 이름을 돌려줍니다. 이후 os.Open은 그 경로를 다시 따라가므로, 두 동작 사이에 관련 디렉터리나 링크가 바뀌면 다른 파일을 열 수 있습니다.

1.3.5에서 남은 간격 · 동작을 단순화한 예시
resolved, err := filepath.EvalSymlinks(requirementsPath)
if err != nil { return err }
if err := checkWithinBuildContext(resolved); err != nil { return err }

// 이 사이에 관련 경로가 바뀔 수 있음
file, err := os.Open(resolved) // 파일 열 때 다시 경로를 조회

checkWithinBuildContext는 설명을 위한 이름이며 실제 함수명이 아닙니다. 핵심은 검사와 열기 사이에 파일시스템 상태가 바뀔 수 있다는 점입니다. 이 TOCTOU 우회를 추가로 전달했고, 1.3.5도 영향받는 버전으로 남게 됐습니다.

두 번째 수정

두 번째 패치 9d575b3에서는 os.OpenRoot와 Root.Open으로 빌드 컨텍스트 디렉터리를 기준으로 파일을 엽니다. 경로 이름만 검사한 뒤 다시 여는 방식에서 벗어나, 파일 탐색 중에도 루트 바깥으로 나가지 않도록 바꾼 것입니다. 이 수정은 1.3.6에 포함됐습니다.

수정된 읽기 방식 · 개념도
root, err := os.OpenRoot(buildContext)
if err != nil { return err }
defer root.Close()

file, err := root.Open(requirementsPath)

회귀 테스트는 이 차이를 디렉터리 교체로 확인합니다. 컨텍스트 디렉터리를 연 뒤 그 디렉터리를 옮기고, 원래 경로에 다른 requirements 파일이 든 디렉터리를 만듭니다. 루트 핸들로 읽으면 처음 연 디렉터리의 파일을 읽고, 경로명으로 다시 열면 교체된 디렉터리의 파일을 읽습니다.

영향과 확인 범위

빌드 입력을 제어할 수 있는 사람이 envd 프로세스의 권한으로 빌드 컨텍스트 밖의 파일을 읽게 만들 수 있는 문제입니다. 1.3.5의 레이스 조건은 관련 경로를 동시에 바꿀 수 있어야 합니다. 읽힌 내용이 requirements 항목으로 처리되면 파일 내용에 따라 의존성 디버그 로그나 빌드 단계 메타데이터에 정보가 남을 수 있습니다.

수정에 포함된 회귀 테스트는 경로 기반 열기와 루트 핸들 기반 열기의 차이를 재현한 테스트입니다. 호스트 파일이 외부로 유출되는 전체 과정을 끝까지 재현한 테스트는 아닙니다. 읽을 수 있는 파일은 envd 실행 권한에 묶이고, 로그에 남는 정보도 파일 내용과 파싱 결과에 따라 달라집니다.

기록처음에는 컨텍스트 경계 누락을 제보했고, 첫 패치 이후에는 검사와 사용 사이의 레이스를 다시 찾아 전달했습니다. 결과적으로 1.3.5의 첫 수정과 1.3.6의 최종 수정, 두 차례 변경으로 이어졌습니다.
